The Problem

Delhi NCR pollution changes with emissions and atmospheric conditions.

High variability

Pollution can change rapidly with wind, temperature, rainfall, atmospheric stability and source activity.

Fragmented information

Ground observations, weather forecasts, satellite fire data and emission inventories come from different systems.

Forecasting challenge

A current AQI describes the present. PureWayu estimates how pollution may evolve over the next 0–72 hours.

System Architecture

Different layers perform different jobs.

01. Data Sources

Weather, ground AQ, satellite/fire, emissions and GIS data.

02. Preprocessing

Cleaning, QC, units, time alignment and spatial mapping.

03. WRF-Chem

Meteorology, atmospheric transport and chemistry simulation.

04. AI / ML

Forecasts using physics, observations and source features.

05. Correction

Uses recent observations to correct systematic errors.

06. Decision Layer

Pollutants → AQI → maps, risk levels and alerts.

Key idea: WRF-Chem provides atmospheric context; AI learns relationships between that context, observations and source information to produce an operational forecast.

Data Layer

Complementary sources are combined instead of relying on one dataset.

Weather

  • GFS / ECMWF forecasts
  • Wind, temperature, humidity and rainfall
  • Boundary-layer and stability information

Ground Air Quality

  • CPCB / SAFAR / OpenAQ where available
  • PM2.5, PM10, O₃, NO₂ and other available pollutants
  • Training, validation and correction

Satellite & Fire

  • VIIRS / MODIS / NASA FIRMS
  • Fire location and timing features
  • Biomass-burning source signals

Emissions & GIS

  • Emission inventories such as EDGAR/REAS where applicable
  • Road, population and land-use context
  • Spatial source/exposure features

WRF-Chem Layer

High-fidelity atmospheric simulation forms the physics layer.

What WRF-Chem does

  • Simulates meteorology and atmospheric chemistry together.
  • Represents pollutant transport and dispersion.
  • Provides boundary-layer and regional-transport information.
  • Produces NetCDF outputs for Python processing.

How PureWayu uses it

  • Define a Delhi-NCR domain including relevant upwind regions.
  • Use temperature, wind, humidity, PBLH and pollutant/aerosol fields.
  • Extract physics-derived features with Python/xarray.
  • Feed those features to the ML forecasting layer.
Compute: WRF-Chem is computationally intensive. Cloud or institutional/HPC resources may be used for high-fidelity simulations; lightweight ML handles routine inference.

AI / ML Models

A lightweight primary model is paired with temporal benchmarks.

XGBoost — Primary

Tree-based model for weather, observations, WRF-Chem, fire and emission features.

  • Fast inference
  • Nonlinear relationships
  • Operationally lightweight

LSTM — Benchmark

Sequence model for temporal pollution and weather patterns.

  • Captures sequential dependencies
  • Useful for comparison

Transformer — Benchmark

Attention-based model for longer and complex temporal relationships.

  • Temporal attention
  • Benchmark against lighter models

Inputs

Pollution + weather + WRF-Chem + fire + emissions + temporal features.

Targets

PM2.5, PM10, O₃, NO₂ and derived AQI.

Evaluation

Chronological split with MAE, RMSE and R² against baseline models.

Observation-Based Bias Correction

The raw forecast is not assumed to be perfect.

Why

Forecast errors can vary by location, season, weather regime and pollution episode.

How

Historical forecast–observation pairs learn systematic errors; recent observations help adjust the current forecast.

Flow: Raw forecast → compare with observations → estimate error → corrected forecast → AQI / alerts.
